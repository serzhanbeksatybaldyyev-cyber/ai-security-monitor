# Sentinel

Интеллектуальная система обнаружения мошеннических SMS и подозрительных ссылок.
Система носит рекомендательный характер: оценка вероятностная и не гарантирует безопасность.

## Запуск

Нужен Python 3.12 или 3.13.

**Windows (PowerShell):**

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

**macOS и Linux:**

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

После запуска откройте http://127.0.0.1:8000/. Команда `seed_demo` создаёт демонстрационные учётные записи:

| Роль | Логин | Пароль | Что увидит |
|---|---|---|---|
| Администратор | `admin` | `AdminDemo2026` | Панель администратора `/panel/` и панель пользователя |
| Пользователь | `demo` | `DemoUser2026` | Панель пользователя с 30 проверками |
| Пользователь | `student_demo` | `Student2026` | 12 проверок, хранение текстов включено |
| Пользователь | `tester_demo` | `Tester2026` | 6 проверок |

Пересоздать демо-данные: `python manage.py seed_demo --reset`. Свой администратор: `python manage.py createsuperuser`.

Если раньше уже запускалась старая версия проекта, удалите файл `db.sqlite3` и снова выполните `migrate` и `seed_demo`: структура базы изменилась.

## Что работает на сайте

| Страница | Адрес | Что можно сделать |
|---|---|---|
| Вход и регистрация | `/login/`, `/register/` | Регистрация с проверкой полей, вход, пауза 60 с после 5 неудачных попыток, выход |
| Dashboard | `/` | Счётчики, средний Risk Score, распределение категорий, проверки по дням с разбивкой по категориям, уровни риска, топ-5 признаков, последние 10 проверок, период 7/30/90 дней |
| Проверка SMS | `/check/sms/` | Текстовая модель из задания 7, словарь признаков, определение языка, проверка ссылок из текста, Risk Score и причины |
| Проверка URL | `/check/url/` | Проверка формата, 22 признака адреса, Risk Score и причины |
| Результат | `/checks/<id>/` | Подробный результат, удаление записи с подтверждением |
| История | `/history/` | Фильтры по дате, типу, категории и риску, страницы по 20 записей, выгрузка CSV |
| Профиль | `/profile/` | Согласие на хранение полного текста SMS, язык, смена пароля, удаление всей истории |
| Статистика | `/stats/` | Графики по дням и категориям, период 7/30/90 дней |

### Панель администратора

Открывается по адресу `/panel/` только для пользователей с ролью администратора. Обычный пользователь получает «Нет доступа» (код 403). Администратор после входа сразу попадает в свою панель и может перейти в панель пользователя кнопкой в меню.

| Раздел | Адрес | Что можно сделать |
|---|---|---|
| Обзор системы | `/panel/` | Статистика по всем пользователям: пользователи, активность, категории, дни, уровни, топ признаков, языки, самые активные пользователи, частые опасные домены, активные версии моделей с метриками |
| Пользователи | `/panel/users/` | Поиск, фильтр по роли и статусу, число проверок у каждого |
| Карточка пользователя | `/panel/users/<id>/` | Блокировка и разблокировка, выдача и снятие прав администратора, очистка истории |
| Все проверки | `/panel/checks/` | Проверки всех пользователей с фильтрами и выгрузкой CSV |
| Модели и правила | `/panel/models/` | Версии моделей и выбор активной, веса Risk Score, словарь признаков, правила для ссылок |
| Журнал действий | `/panel/audit/` | Кто, когда и что изменил, блокировки входа после 5 неудачных попыток |
| База данных | `/admin/` | Стандартная админка Django для главного администратора |

Ограничения по ТЗ (ФТ-1.9): администратор не видит тексты чужих SMS и ссылки. Ему показываются только результаты: дата, тип, язык, категория, риск. Свою учётную запись и учётную запись главного администратора из панели менять нельзя.

### База данных

Таблицы соответствуют разделу 4.3 ТЗ: `user_profile`, `checks`, `url_results`, `detected_features`, `model_versions`, плюс `admin_actions` для журнала. ER-диаграмма: `docs/diagrams/er_diagram.png`. Её можно пересобрать командой `python docs/diagrams/build_er.py`.

- По умолчанию используется SQLite (файл `db.sqlite3`).
- Для PostgreSQL установите `pip install -r requirements-postgres.txt` и в `.env` укажите `DB_ENGINE=postgresql` и параметры `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`.
- Каждая проверка вместе со ссылками и признаками сохраняется в одной транзакции.
- Без согласия пользователя полный текст не хранится (`input_text = NULL`). В `input_masked` телефоны, номера карт, суммы и коды заменены на `***`.

Что пока временно:

- URL-модели ещё нет (задания 10–11), поэтому вероятность опасности ссылки считают правила по признакам адреса.
- Веса и пороги Risk Score заданы в `ml/risk_config.yaml` вручную и будут подобраны на валидации в задании 13.
- Текстовая модель обучена на английских SMS. Для русского и казахского её вклад в оценку уменьшен, и об этом пишет страница результата.

## REST API (раздел 4.4 ТЗ)

Сессионная авторизация, единый формат ошибок `{"error": {"code": ..., "message": ...}}`, лимит 30 проверок в минуту (429).

| Метод | Адрес | Назначение |
|---|---|---|
| POST | `/api/v1/auth/register/`, `/login/`, `/logout/` | Регистрация (201), вход (200/401/429), выход (204) |
| POST | `/api/v1/check/sms/`, `/check/url/` | Анализ SMS `{"text": ...}` и ссылки `{"url": ...}` |
| GET | `/api/v1/checks/` | История, фильтры `date_from`, `date_to`, `type`, `category`, `risk_level`, `page` |
| GET, DELETE | `/api/v1/checks/<id>/` | Результат и удаление своей записи (чужая запись даёт 404) |
| GET | `/api/v1/stats/summary/` | Данные для Dashboard |
| GET | `/api/v1/health/` | Состояние и модели |

Страницы проверки используют этот API через fetch без перезагрузки; без JavaScript работает обычная отправка формы.

## Интерфейс

Тёмная и светлая темы (переключатель в меню), боковое меню, Chart.js и шрифты лежат в `static/vendor/` и работают без интернета. Цвета тревоги используются только для категорий риска, у каждой категории есть иконка и текст.

## Данные и модель

Очищенные данные, индексы разбиения и базовая модель уже лежат в репозитории. Чтобы пересоздать их, выполните команды из корня проекта:

```bash
python -m ml.data.load_sms     # data/processed/sms_raw.csv
python -m ml.data.clean_sms    # data/processed/sms_clean.csv и отчёт
python -m ml.split             # data/processed/sms_split.json
python -m ml.baseline          # первая модель только на английском: ml/artifacts/sms_baseline.joblib
python -m ml.data.generate_ru_kk   # русский и казахский корпуса: data/raw/synthetic_ru.csv, synthetic_kk.csv
python -m ml.multilingual      # рабочая модель en+ru+kk: ml/artifacts/sms_multilingual.joblib и отчёт метрик
```

Три корпуса одинакового размера (по 5 137 SMS, 12,09% мошеннических). Английский набор настоящий (UCI),
русский и казахский искусственные: см. `docs/08_multilingual_report.md`. Русский и казахский делятся на выборки по группам шаблонов,
а независимая проверка идёт на рукописном наборе `data/raw/custom_ru_kk.csv`.

Сверка набора с официальным архивом UCI (нужен интернет):

```bash
python -m ml.data.verify_source
```

Проверить модель на своём тексте:

```bash
python -c "from ml.baseline import predict_sms; print(predict_sms('You won a prize! Call now'))"
```

Модель обучена только на английских SMS. Для русского и казахского её оценка пока ненадёжна.

Ноутбуки находятся в `notebooks/`. Запуск: `jupyter notebook`.
